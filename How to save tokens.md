<mark>1. Immediate "Easy Wins" (Prompting & Chat Habits) Start Fresh Chats (/clear or /cle): The single highest-impact token-saving habit . When you finish a task, or switch to an unrelated topic in the same session, run the clear command to wipe the slate clean . This resets your compounding token cost back to zero . Edit Your Mistakes Instead of Replying: When Claude makes a mistake or writes broken code, do not send a follow-up correction like "No, that's wrong, fix it" . Follow-ups stack onto the chat history permanently . Instead, click edit on your original prompt, fix the wording, and hit regenerate to replace the bad exchange entirely . Batch Your Questions: Combine multiple tasks or questions into a single message . Three separate back-and-forth messages cost three times what one combined message costs . Be Surgical with Pasting: Never dump a massive 50-page PDF or an entire file if you only need Claude to look at a single function or paragraph . Carry the Answer, Not the Argument: When doing multi-step work (such as brainstorming followed by coding), don't keep the brainstorming history. Ask Claude to generate a clean "handoff" summary of the decisions, clear the chat, and paste just that summary into a new chat to begin coding . Ask for Concise Outputs: Output tokens cost more than input tokens and get added to your input on subsequent turns . Tell Claude to give you precisely what you need (e.g.,</mark> " <mark>give me 5 bullets</mark> " <mark>or</mark> " <mark>reply in under 150 words</mark> " <mark>) . You can even stop saying</mark> " <mark>please</mark> " <mark>and</mark> " <mark>thank you</mark> " <mark>to save extra characters .</mark> 

<mark>2. Claude Code Built-In Commands & Configuration Keep your claude.md File Lean: While using a project-level claude.md file is a great built-in feature to load project context automatically , it gets read on every single message . Keep this file under 200–300 lines (focused on tech stack, key rules, and file structures) . If your claude.md is bloated, you are paying a heavy "invisible context tax" from the very first message . Run /compact at 50%–60% Context: The built-in /compact command summarizes your active history into a clean checkpoint . Do not wait for Claude's "auto-compact" at 95% ; by then, the context window is degraded, and it may throw an out-of-space error . Check your usage percentage regularly using /context and /cost . Surgically Reference Files: Avoid vague requests like "fix the auth flow" which force Claude to scan your whole repo . Point Claude directly to files or functions (e.g., using @filename or explicit paths like @auth.js) so it only reads the relevant code . Disconnect Unused MCP Servers: Connected Model Context Protocol (MCP) servers (like GitHub, Slack, or Sentry) load their entire tool definitions into your context on every single turn . A setup with multiple active servers can burn roughly 55,000 tokens of invisible overhead before you even type your first prompt . Disconnect servers you aren't using . Use Plan Mode First: Before letting Claude modify or write code across multiple files, ask it to map out a plan first . Correcting code that was written under a misunderstanding is incredibly token-intensive .</mark> 

<mark>3. Specialized Open-Source Repos & Skills RTK (CLI Output Compressor): Sits as a proxy between Claude and your terminal . When Claude runs command-line tools (such as git diff, git log, or test runners), RTK filters out comments, whitespaces, groups duplicate error outputs, and truncates long descriptions . It filters the noise before it enters your conversation history, saving 60% to 90% of command-related tokens . Caveman Skill: A custom skill that forces Claude to drop polite conversational filler and explain things in very direct, ultra-concise language while keeping 100% of the technical accuracy . It can cut output token costs by up to 30% to 75% . Graphy / CodeGraph: Pre-indexes your codebase into a queryable semantic knowledge graph . Instead of Claude having to chunk and search your files using grep back-and-forth, it queries this static map to find files instantly, cutting down on retrieval tokens . Headroom: A proxy wrapper that intercepts messages to Claude and compresses conversation histories by removing redundant and repetitive data without losing variables or key decisions . Ponytail: A skill that forces Claude to behave like a "lazy senior developer," writing highly optimized code using as few lines as possible, minimizing the cost of generating bloated files . Intent Layers: Automatically scans directories in your project and places nested markdown files in any folder exceeding 20,000 tokens . This gives Claude hyper-local explanations of directory rules and prevents it from reading files blindly .</mark>
